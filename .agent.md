# MindCubby Design System Agent Rules

## Component Usage Rules

### 1. No Emojis in Components
- ❌ **Don't**: Use emoji characters like `→`, `✓`, `✗` in component content
- ✅ **Do**: Use icon components (`<labs-icon>`) or proper Unicode symbols in text-only contexts
- **Example Fix**: 
  - Bad: `<labs-button>Open →</labs-button>`
  - Good: `<labs-button>Open <labs-icon name="keyboard_arrow_right" slot="icon-right"></labs-icon></labs-button>`

### 2. Icon Component for Actions
- Use `<labs-icon>` with `slot="icon-right"` or `slot="icon-left"` for button icons
- Available icons: `keyboard_arrow_right`, `keyboard_arrow_left`, `add`, `delete`, `edit`, `settings`, etc.
- See `/smoothie/foundations/icons/` for complete icon list

### 3. Breadcrumbs Simplification
- Don't repeat "Smoothie Design System" on every page breadcrumb
- Breadcrumb structure: `[Section Number]. [Section Name] / [Page Name]`
- Example: `1. Foundations / Container` (not `Smoothie Design System / 1. Foundations / Container`)
- Links should point to parent sections, not back to home

### 4. Color Tokens & Styling
- Use design system color variables instead of hardcoded values
- For separators/outlines: `var(--color-outline, #ddd)` instead of `#999`
- For text: `var(--color-on-surface-variant, #999)` for secondary text
- Gray backgrounds/borders should be lighter for better theme support

### 5. Documentation Pages
- Avoid redundant text in breadcrumbs and section headers
- Use consistent heading hierarchy: Demo → About → Technical Details
- Apply proper gap/spacing between grid items (use `gap: 1.5rem` or `2rem`)

### 6. Text and Copy Guidelines
- Remove "Smoothie Design System" from repeated breadcrumb items
- Keep component descriptions concise and focused on use cases
- Use action-oriented language for buttons

## File Patterns

### Component Pages
- Location: `/smoothie/components/[name]/index.html`
- Layout: Back button → Breadcrumbs → Title → Demo → About/Details
- Imports: Always include breadcrumbs component

### Foundation Pages  
- Location: `/smoothie/foundations/[name]/index.html`
- Same layout as component pages
- Focus on design principles and usage patterns

### Pattern Pages
- Location: `/smoothie/patterns/[name]/index.html`
- Show real-world compositional examples
- Link to actual apps/use cases

## Component Quality Checklist

- [ ] No emoji characters in UI content
- [ ] All interactive icons use `<labs-icon>` component
- [ ] Breadcrumbs follow simplified format
- [ ] Color tokens used instead of hardcoded colors
- [ ] Proper spacing/gap in grid layouts
- [ ] No "Smoothie Design System" repetition
- [ ] Responsive design tested
- [ ] Theme variables support (light/dark, multiple themes)
